## 작업: 아이덴티티 UI 이미지 구조 보강

### 작업 배경

- 아이덴티티 UI를 기존 설명 텍스트 중심 자리표시에서 User Widget에 어울리는 이미지 중심 구조로 변경하기로 했다.
- 현재 기본 전투 흐름은 주먹/권을 사용하므로, 기본 아이덴티티 아이콘으로 회색 돌주먹 이미지를 준비했다.
- 아이덴티티 이미지 아래에는 앞으로 무기별 기력, 마력, 특수 자원 같은 전용 게이지가 배치될 예정이다.

### 작업 내용

- `FRogue10mHudIdentityView`에 Widget Blueprint에서 사용할 아이덴티티 표시 데이터를 추가했다.
  - 무기 타입
  - 숙련도 레벨
  - 숙련도 정규화 값
  - 외곽선 색
  - 외곽선 굵기
  - 특수 자원 라벨
  - 아이콘 텍스처 참조
- `URogue10mRunHUD::GetIdentityView()`에서 현재 무기 숙련도에 비례해 외곽선 색과 굵기를 계산하도록 했다.
- 권 또는 기본 주먹 상태에서는 `/Game/UI/Icons/T_Identity_StoneFist` 경로의 아이콘 텍스처를 사용하도록 준비했다.
- 기본 아이콘 원본으로 `Content/UI/Icons/T_Identity_StoneFist.png`를 추가했다.
  - 생성된 회색 돌주먹 이미지를 프로젝트에 복사했다.
  - UI에서 쓰기 쉽도록 배경을 알파 처리했다.
- `Docs/WidgetBlueprintHUDGuide.md`에 `WBP_Identity` 내부 권장 구조와 바인딩 값을 추가했다.
- Lazy Codex 하네스 규칙에 맞춰 `Feature/architect/2026-07-02_identity-ui.md`, `Feature/doc/2026-07-02_identity-ui.md`를 작성했다.

### Widget Blueprint 작업 메모

- `WBP_Identity` 내부 권장 구조는 다음과 같다.

```text
CanvasPanel Root
├─ Border_IdentityOutline
│  └─ Overlay
│     ├─ Image_IdentityIcon
│     └─ Text_MasteryLabel
└─ ProgressBar_IdentityResource
```

- `Image_IdentityIcon`은 `GetIdentityView().IconTexture`를 사용한다.
- `Border_IdentityOutline`은 `GetIdentityView().OutlineColor`, `GetIdentityView().OutlineThickness`를 사용한다.
- `Text_MasteryLabel`은 `GetIdentityView().Label`을 사용한다.
- `ProgressBar_IdentityResource`는 `GetIdentityView().Normalized`를 사용한다.

### 남은 확인 사항

- `T_Identity_StoneFist.png`는 PNG 원본이므로 Unreal Editor에서 Texture Asset으로 import해야 한다.
- import 시 경로와 이름을 `/Game/UI/Icons/T_Identity_StoneFist`로 맞추면 C++의 기본 아이콘 참조와 연결하기 쉽다.
- 실제 UI 배치와 크기 조정은 `WBP_Identity` Designer에서 확인한다.

## 작업: HUD를 Widget Blueprint 바인딩 중심 구조로 정리

### 작업 배경

- 기존 HUD는 `DrawRect`, `DrawText`를 이용한 Canvas 직접 그리기 원형 UI가 남아 있었다.
- 앞으로 UI 배치와 디자인은 Unreal Editor의 Widget Blueprint에서 직접 진행할 예정이므로, C++는 데이터를 제공하고 Widget Blueprint가 Bind하는 방식으로 정리했다.

### 작업 내용

- Canvas 원형 HUD의 기본 표시 값을 껐다.
  - `ARogue10mHUD::bDrawCanvasPrototypeHUD` 기본값을 `false`로 변경했다.
  - Canvas 원형 HUD가 꺼진 상태에서는 피격 효과와 드래그 아이템도 C++ Canvas로 직접 그리지 않도록 했다.
- 자동 Prototype UI 생성 기본값을 껐다.
  - `URogue10mMainHUDWidget::bCreatePrototypeLayoutWhenEmpty` 기본값을 `false`로 변경했다.
  - `URogue10mHudPartWidget::bCreatePrototypeDesignScaffold` 기본값을 `false`로 변경했다.
- Widget Blueprint에서 직접 사용할 수 있는 View Getter를 추가했다.
  - `GetRunTimerView`
  - `GetRunResultView`
  - `GetAimCrossLineView`
  - `GetDamageFeedbackView`
  - `GetAttackCooldownView`
- 공격 쿨타임 View에는 현재 공격 스킬 이름, 아이콘, 아이콘 라벨, 아이콘 색, 남은 쿨타임, 전체 쿨타임, 쿨타임 비율을 담았다.
- 에임 View에는 표시 여부, 색상, 라인 길이, 간격, 굵기를 담았다.
- 피격 효과 View에는 표시 여부, 알파, 강도를 담았다.
- `Docs/WidgetBlueprintHUDGuide.md` 상단에 현재 기준의 Widget Blueprint 직접 배치/바인딩 가이드를 추가했다.

### 검증 결과

- `powershell -ExecutionPolicy Bypass -File .\Scripts\BuildEditor.ps1` 실행 결과 C++ 빌드가 성공했다.
- `powershell -ExecutionPolicy Bypass -File .\Scripts\CheckGeneratedChanges.ps1` 실행 결과 하네스 경로 검사가 통과했다.
- 생성물 검사에서 `Content/Widget/Parts/*.uasset` 변경 경고가 표시되었지만, 해당 변경은 작업 시작 전부터 존재하던 Widget Blueprint 바이너리 변경이다.

### Notion 정리 후보

- 메인 HUD는 Widget Blueprint가 UI 요소를 직접 배치하고 C++ Getter로 데이터를 가져오는 구조를 기본으로 한다.
- C++ Canvas HUD는 임시/디버그 원형으로만 남겨두며 기본값은 비활성화한다.
- 주요 런타임 UI 데이터는 `URogue10mRunHUD`의 `Get*View` 함수로 접근한다.
- `BindWidgetOptional` 자동 연결은 하위 위젯 인스턴스 이름을 C++ 변수명과 정확히 맞췄을 때만 사용한다.
## 작업: 사용하지 않는 템플릿 C++ 클래스 및 Variant 콘텐츠 정리

### 작업 배경

- 프로젝트 생성 시 포함된 Shooter/Horror Variant 템플릿 클래스와 전용 콘텐츠가 현재 Rogue10m 플레이 흐름에서 사용되지 않는 상태였다.
- 사용하지 않는 C++ 클래스와 관련 템플릿 에셋을 제거해 프로젝트 구조를 가볍게 만들고, 앞으로 실제 게임 기능 중심으로 관리하기 쉽도록 정리했다.

### 작업 내용

- `Source/Rogue10m/Variant_Shooter/**` C++ 클래스를 제거했다.
- `Source/Rogue10m/Variant_Horror/**` C++ 클래스를 제거했다.
- 제거한 클래스에만 연결된 템플릿 전용 콘텐츠도 함께 정리했다.
  - `Content/Variant_Shooter/**`
  - `Content/Variant_Horror/**`
  - `Content/__ExternalActors__/Variant_Shooter/**`
  - `Content/__ExternalActors__/Variant_Horror/**`
  - `Content/__ExternalObjects__/Variant_Shooter/**`
  - `Content/__ExternalObjects__/Variant_Horror/**`
- 총 311개 추적 파일을 제거했다.
- 대략 5.66MB 규모의 템플릿 전용 파일이 작업 트리에서 줄었다.

### 남겨둔 항목

- `Content/Weapons` 및 Mannequin 계열 무기 애니메이션은 바로 삭제하지 않았다.
- 해당 리소스는 이후 실제 주먹/무기 전투 애니메이션과 충돌 여부를 확인한 뒤 별도 콘텐츠 최적화 작업에서 정리하는 편이 안전하다.

- `powershell -ExecutionPolicy Bypass -File .\Scripts\CheckGeneratedChanges.ps1` 실행 결과 Harness 경로 체크를 통과했다.
- CheckGeneratedChanges에서 삭제된 `.uasset/.umap`에 대한 바이너리 에셋 경고가 표시되었지만, 이번 작업에서 의도적으로 Variant 전용 콘텐츠를 제거했기 때문에 기록 가능한 경고로 판단했다.

### Notion 정리 후보

- 사용하지 않는 UE 템플릿 Shooter/Horror Variant C++ 클래스와 전용 콘텐츠를 제거했다.
- 현재 Rogue10m 메인 플레이, UI, 전투, 인벤토리, 스킬 데이터 흐름은 별도 구조를 사용하므로 해당 Variant 클래스는 빌드 의존성이 없다.

## 작업: UE 5.8 전환 및 MCP 플러그인 장착

### 작업 배경

- UE 5.8 다운로드가 완료되어 Rogue10m 프로젝트를 UE 5.7 기반 설정에서 UE 5.8 기반 설정으로 전환했다.
- UE 5.8에 포함된 실험 기능인 MCP 플러그인을 프로젝트에서 사용할 수 있도록 활성화했다.

### 작업 내용

- `Rogue10m.uproject`의 `EngineAssociation`을 `5.8`로 변경했다.
- 프로젝트 플러그인 목록에 다음 플러그인을 추가했다.
  - `ModelContextProtocol`
  - `MCPClientToolset`
- `Scripts/BuildEditor.ps1`, `Scripts/PackageWindows.ps1`, `Scripts/PackageAndroid.ps1`의 엔진 경로를 `D:\Program Files\UE_5.8`로 변경했다.
- `Rogue10m.Target.cs`, `Rogue10mEditor.Target.cs`의 빌드 설정을 UE 5.8 기준으로 변경했다.
  - `DefaultBuildSettings = BuildSettingsVersion.V7`
  - `IncludeOrderVersion = EngineIncludeOrderVersion.Unreal5_8`
- 이전 Variant 템플릿 정리로 삭제된 폴더가 `Rogue10m.Build.cs` include path에 남아 있어 경고가 발생하던 부분을 제거했다.
- `AGENTS.md`, `Docs/HarnessPipeline.md`, `Docs/UnrealEngineeringRules.md`, `Docs/Rogue10m_PrototypePlan.md`의 엔진 버전 및 경로 설명을 UE 5.8 기준으로 갱신했다.
- `Docs/UE58MCPSetup.md`를 추가해 MCP 플러그인 위치, 기본 서버 설정, Rogue10m 적용 후보를 정리했다.

### 검증 결과

- UE 5.8 `Build.bat -projectfiles`로 프로젝트 파일 재생성을 완료했다.
- `powershell -ExecutionPolicy Bypass -File .\Scripts\BuildEditor.ps1` 실행 결과 성공했다.
- `powershell -ExecutionPolicy Bypass -File .\Scripts\CheckGeneratedChanges.ps1` 실행 결과 Harness 경로 체크를 통과했다.

### 확인된 사항

- 프로젝트 파일 생성 중 Android SDK 설정이 없어 Android 플랫폼이 스킵되었다. Android 패키징 검증은 SDK 세팅 후 별도 진행이 필요하다.
- `CheckGeneratedChanges.ps1`에서 Variant 템플릿 삭제분에 대한 바이너리 에셋 경고가 표시되었지만, 이전 최적화 작업의 의도된 삭제 항목이다.
- MCP 서버 자동 시작과 포트 설정은 `EditorPerProjectUserSettings` 성격이 있으므로 저장소에는 플러그인 활성화만 반영했다.
- 에디터에서 `Project Settings > Model Context Protocol`을 열어 서버 자동 시작, 포트, 도구 검색 설정을 확인하면 된다.

### Notion 정리 후보

- Rogue10m 프로젝트를 UE 5.8 기준으로 전환했다.
- UE 5.8의 실험 MCP 플러그인 `ModelContextProtocol`과 `MCPClientToolset`을 활성화했다.
- MCP는 C++/Widget/Data Asset 상태 점검, 미사용 에셋 탐색, 빌드 로그 분석, DevLog 정리 자동화에 우선 활용할 예정이다.
- Editor 빌드는 성공했으며 Android 패키징은 SDK 환경 세팅 후 별도 검증이 필요하다.
## 작업: 스킬 시스템 GAS 전환 1단계 기반 추가

### 작업 배경

- 기존 공격과 스킬은 `Rogue10mCombatComponent`와 `Rogue10mAttackSkillData` 중심으로 직접 처리되고 있었다.
- 앞으로 무기별 스킬, 숙련도, 자원 비용, 쿨타임, 버프/디버프가 늘어날 예정이므로 Unreal Gameplay Ability System 기반으로 점진 전환하기로 했다.

### 작업 내용

- `GameplayAbilities` 플러그인을 프로젝트에 활성화했다.
- `Rogue10m.Build.cs`에 `GameplayAbilities`, `GameplayTags`, `GameplayTasks` 모듈 의존성을 추가했다.
- `Source/Rogue10m/Ability` 폴더를 추가하고 GAS 전용 클래스를 만들었다.
  - `URogue10mAbilitySystemComponent`
  - `URogue10mAttributeSet`
  - `URogue10mGameplayAbility_Attack`
- `Rogue10mPlayerState`가 `IAbilitySystemInterface`를 구현하도록 변경했다.
- `Rogue10mPlayerState`에 `AbilitySystemComponent`와 `AttributeSet`을 배치했다.
- `Rogue10mCharacter`가 PlayerState의 ASC를 사용하도록 `IAbilitySystemInterface`를 구현했다.
- 캐릭터 소유 시점과 PlayerState 복제 시점에 ASC ActorInfo를 초기화하도록 연결했다.
- 기본 공격 Ability를 캐릭터가 보유하도록 grant하는 흐름을 추가했다.
- `Rogue10mAttackSkillData`에 스킬별 `GameplayAbilityClass`를 지정할 수 있는 필드를 추가했다.
- 공격 실행 시 먼저 GAS Ability 활성화를 시도하고, 실패하면 기존 공격 실행 로직으로 전환하도록 브리지 구조를 만들었다.

### 현재 구조

- 현재 GAS Ability는 기존 공격 로직을 대체하지 않고 호출하는 전환용 브리지다.
- 기존 콤보, 공격 판정, 데미지 적용, 자원 소비, 쿨타임 UI는 그대로 유지된다.
- 비용과 쿨타임은 아직 GameplayEffect가 아니라 기존 로직을 사용한다.

### 검증 결과

- `powershell -ExecutionPolicy Bypass -File .\Scripts\BuildEditor.ps1` 실행 결과 성공했다.
- `powershell -ExecutionPolicy Bypass -File .\Scripts\CheckGeneratedChanges.ps1` 실행 결과 Harness 경로 체크를 통과했다.
- CheckGeneratedChanges에서 Variant 템플릿 삭제분에 대한 바이너리 에셋 경고가 표시되었지만, 이전 최적화 작업의 의도된 삭제 항목이다.

### 다음 작업 후보

- `AttributeSet`의 체력, 스테미나, 마나를 기존 `VitalsComponent`와 동기화한다.

- 스킬 해금 상태를 GameplayTag 또는 ASC Granted Ability로 연결한다.
- 몬스터도 ASC/AttributeSet 기반 데미지 처리로 확장한다.

### Notion 정리 후보

- Rogue10m 스킬 시스템 GAS 전환 1단계를 적용했다.
- PlayerState가 ASC와 AttributeSet을 소유하고 Character는 PlayerState ASC를 사용한다.

## 작업: UE 5.8 MCP Toolset 기반 메인 HUD 위젯 배치 연결

### 작업 배경

- UE 5.8 MCP 서버가 `8010` 포트에서 정상 응답하는지 확인했다.
