# 장비창 우측 슬롯 3열 배치 정리

## 작업 목표

장비창 우측 장비 슬롯을 사용자가 요청한 행 기준으로 정돈하고, 무기 슬롯은 가운데 행의 독립된 세 번째 열에 배치했다.

## 주요 변경

- 장비 슬롯 Canvas를 300x500에서 350x500으로 확장하고 우측 경계는 유지했다.
- 슬롯 행을 `투구 | 목걸이`, `갑옷 | 장갑 | 무기`, `신발 | 반지`로 재구성했다.
- 기존 부위별 슬롯 크기와 아이콘 `ScaleToFit` 규칙은 유지했다.
- 장비창 전용 재생성 스크립트와 통합 검증 스크립트의 좌표·컨테이너 크기 계약을 갱신했다.
- Unreal Editor API로 `WBP_EquipmentWindow`만 재생성·컴파일·저장했다.

## 검증

- Python `py_compile` 통과
- 장비창 Designer 필수 위젯 19개 및 전체 위젯 46개 확인
- 컨테이너 위치 `(180, -5)`, 크기 `350x500` 확인
- 7개 슬롯 좌표와 부위별 고정 크기 자동 검사 통과

## Notion 요약 후보

장비창 우측 슬롯을 3행 구조로 재배치했다. 상단은 투구·목걸이, 중앙은 갑옷·장갑·무기, 하단은 신발·반지로 구성하며 무기는 중앙 우측의 세 번째 열에 둔다. 기존 슬롯 크기와 아이콘 종횡비 보존 규칙은 그대로 유지했고, Editor 자동 재생성 및 좌표 검증까지 완료했다.

## 장비 아이콘 슬롯 경계 넘침 수정

장비창 슬롯 좌표는 정상이어도 투구·갑옷·신발·무기 이미지가 원본 크기로 겹쳐 표시되는 문제를 수정했다.

### 원인

- `SetBrushFromTexture(..., true)`가 Texture 원본 크기를 Image Desired Size로 복사했다.
- GridPanel이 투구 512x512, 갑옷 512x768, 무기 256x768 Desired Size를 그대로 셀 크기로 사용해 ScaleBox가 슬롯 크기로 제한되지 않았다.

### 수정

- 슬롯 레이어를 GridPanel에서 고정 경계용 CanvasPanel로 변경했다.
- ScaleBox는 슬롯 사방 7px Stretch Anchor, 위치 텍스트는 우측 상단 `(-4, 3)` AutoSize 및 ZOrder 1로 고정했다.
- Texture 원본 종횡비를 유지하면서 긴 변을 64px로 정규화하고, 최종 크기는 ScaleBox가 결정하도록 변경했다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- PIE 장착 아이콘 Desired Size: 투구 64x64, 갑옷 42.67x64, 무기 21.33x64
- 저장된 장비창 7슬롯 Canvas 계층·Stretch Anchor·7px 여백·라벨 Anchor 및 ZOrder 검사 통과

### Notion 요약 후보

장비창 장착 이미지가 슬롯 밖으로 크게 겹치던 원인은 원본 Texture Desired Size와 GridPanel 셀 계산의 결합이었다. 슬롯 레이어를 CanvasPanel로 교체하고 아이콘 긴 변을 64px로 정규화한 뒤 ScaleBox가 사방 7px 내부에서 최종 크기를 결정하도록 수정했다.

### 적용 규격

- 갑옷: 100x150

- 기존 사방 7px 아이콘 여백, 우측 상단 라벨 Anchor, ZOrder 1 계약 유지
- `WBP_EquipmentWindow` 재생성·컴파일·저장 성공

## 장비창 왼쪽 캐릭터 스탯 패널 준비

캐릭터 프리뷰 왼쪽에 능력치 정보를 표시할 수 있도록 장비창을 3열 구조로 확장했다.

### 레이아웃

- 장비창: 980x620, 초기 중심 위치 (200, 0)
- 왼쪽: 200x500 스탯 패널
- 중앙: 340x500 실시간 캐릭터 프리뷰
- 오른쪽: 350x500 장비 슬롯 Canvas

### 스탯 필드

- 공격력, 방어력, 최대 체력, 치명타 확률, 공격 속도, 이동 속도
- 각 Text는 Widget Blueprint 변수이며 C++ `BindWidgetOptional` 멤버로 노출했다.
- 현재 값은 0 자리표시자이며 실제 플레이어 스탯 소스 연결을 위한 UI 계약까지 준비했다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- 장비창 필수 Widget 27개, 전체 Designer Widget 52개 확인
- 980x620 창과 3개 패널 위치·크기, 7개 스탯 Text·폰트 검사 통과

### Notion 요약 후보

장비창을 980x620으로 확장해 왼쪽 200x500 스탯 패널, 중앙 캐릭터 프리뷰, 오른쪽 장비 슬롯의 3열 구조로 구성했다. 공격력·방어력·최대 체력·치명타 확률·공격 속도·이동 속도 Text를 Widget 변수와 C++ BindWidgetOptional 멤버로 준비했으며, 실제 스탯 데이터 소스만 연결하면 표시할 수 있다.


## 인벤토리·장비창 동시 상호작용 입력 투과

장비창이 열려 있을 때 전체화면 투명 영역이 아래 인벤토리의 마우스 입력을 막는 문제를 수정했다.

### 원인

- 인벤토리와 장비창은 각각 전체화면 UserWidget이며 동일한 Viewport ZOrder 50에 생성된다.
- 나중에 생성된 장비창이 `Visible` 상태로 전체 화면 Hit Test 경로를 차지했다.

### 수정

- 열린 메뉴 UserWidget을 `SelfHitTestInvisible`로 변경했다.
- `UI_InventoryCanvas`와 `UI_EquipmentCanvas`도 `SelfHitTestInvisible`로 저장했다.
- 실제 WindowRoot 자식, 드래그 핸들, 인벤토리 아이템과 장비 슬롯은 기존 입력 상태를 유지했다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- PIE PlayerController에서 인벤토리·장비창 상태가 동시에 `True`
- 두 UserWidget과 화면 Canvas는 입력 투과, 실제 드래그 핸들과 장비 슬롯은 `Visible` 확인
- 전체 메뉴 Widget Blueprint 컴파일 및 참조 검사 통과
- computer-use 실제 마우스 자동화는 Windows ACL 초기화 오류로 실행하지 못함


## 장비 아이템을 인벤토리로 옮기는 Drag & Drop 구현

### 작업 목표

장비창에 장착된 아이템을 인벤토리의 원하는 빈 Grid 위치로 끌어 장착 해제할 수 있게 구현했다. 아이템마다 다른 `InventorySize(MxN)`를 유지하며, 배치 실패 시 장비 상태가 변경되지 않도록 했다.

### 주요 변경

- 장비 전용 Drag Source와 장비 부위, Item Data, 수량, 클릭 셀 오프셋 Payload를 추가했다.
- 장비창의 7개 슬롯 Frame을 Drag 시작 영역으로 연결했다.
- 인벤토리 DragOver/Drop이 기존 Grid 아이템과 장비 아이템을 모두 처리하도록 확장했다.
- `TryUnequipItemToGrid()`에서 MxN 빈 공간을 재검증한 뒤 Grid 추가와 장비 해제를 함께 처리한다.
- 성공 시에만 인벤토리/장비 변경 Delegate를 방송하고, 취소·겹침·경계 밖 Drop은 장비를 유지한다.
- 시작 장비가 장착 상태와 Grid에 동시에 존재하던 중복을 제거했다.
- 주무기 해제 성공 시 캐릭터 무기 타입을 비무장으로 되돌린다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- 전체 메뉴 Widget Blueprint commandlet 컴파일 성공
- `ValidateMenuWidgetAssets.py` 통과, 0 errors / 0 warnings
- `git diff --check` 통과
- Remote Execution 비활성 상태로 실제 마우스 Drop은 PIE 수동 QA 필요

### 확인할 점

1. 빈 칸 Drop 성공 시 장비 슬롯이 비고 동일 아이템이 정확한 MxN 크기로 생성되는지 확인
2. 점유 칸·Grid 밖·인벤토리 밖 Drop에서 장비가 유지되는지 확인
3. 주무기 해제 후 비무장 상태가 반영되는지 확인

### Notion 요약 후보


## 메뉴 창 호출 순서 기반 ZOrder 스택

### 작업 목표

인벤토리 UI와 장비창 UI가 겹쳤을 때 더 늦게 호출된 창을 위에 표시하고, 아래 창의 노출 영역을 클릭하면 해당 창이 다시 최상단으로 올라오게 한다.

### 주요 변경

- PlayerController에 `TWeakObjectPtr` 기반 메뉴 창 순서 스택을 추가했다.
- 창 열기 또는 좌클릭 시 해당 창을 스택 마지막으로 이동시키고 ZOrder `50 + Index`를 다시 적용한다.
- 반복 호출에도 ZOrder가 무한히 증가하지 않고 현재 메뉴 창 수 범위 안에서만 재정렬된다.
- `SetWindowOpen(true)` 직접 호출과 공통 Preview Mouse 입력 경로 모두 동일한 승격 규칙을 사용한다.
- 입력 Focus가 인벤토리 고정 우선순위가 아니라 현재 최상단의 열린 메뉴 창을 따르도록 수정했다.
- 인벤토리·장비창 동시 표시 중 상태가 바뀌지 않은 창은 재적용하지 않아 호출 순서를 보존한다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- 전체 메뉴 Widget Blueprint commandlet 컴파일 성공
- `ValidateMenuWidgetAssets.py` 0 errors / 0 warnings
- PIE 실제 겹침·클릭 승격·Drag & Drop 상호작용은 수동 QA 필요

### Notion 요약 후보

- 인벤토리·장비창을 호출 순서 기반의 제한된 ZOrder 스택으로 변경
- 나중에 연 창이 위에 표시되고, 아래 창의 노출 영역을 클릭하면 다시 최상단으로 승격
- 최상단 메뉴를 기준으로 키보드 Focus 동기화
- C++ 빌드 및 전체 메뉴 WBP 컴파일 검증 완료, PIE 수동 상호작용 QA 대기

## 인벤토리 아이템 Hover 툴팁 UserWidget

### 작업 목표

인벤토리 아이템에 마우스를 올리면 Item Data Asset의 아이템 이름, 아이템 정보, 무게를 별도 UserWidget으로 표시한다.

### 주요 변경

- `URogue10mInventoryItemTooltipWidget` C++ 부모 클래스를 추가했다.
- `WBP_InventoryItemTooltip`을 생성하고 이름·설명·무게 TextBlock을 구성했다.
- Inventory Item 초기화 시 Tooltip UserWidget을 만들고 Unreal 기본 `SetToolTip()`에 연결했다.
- 설명이 비어 있는 아이템에는 대체 안내 문구를 표시한다.
- 단일 아이템은 개당 무게, 중첩 아이템은 개당 무게·수량·총 무게를 함께 표시한다.
- Drag Preview의 Tooltip은 제거해 드래그 중 설명 UI가 따라오지 않도록 했다.
- 실행 중 Editor가 기존 `WBP_InventoryItem`을 잠그는 상황을 피하기 위해 편집 가능한 native `TSoftClassPtr` 기본 경로로 툴팁 클래스를 연결했다.
- 중앙 메뉴 빌더와 좁은 Tooltip 생성 스크립트, 전체 Validator에 새 WBP 계약을 추가했다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- `WBP_InventoryItemTooltip` 생성·저장 성공
- 전체 메뉴 Widget Blueprint commandlet 컴파일 성공
- 필수 TextBlock 3개와 native Tooltip Soft Class 기본값 검증 성공
- 최종 0 errors / 0 warnings
- 실제 Hover 위치·표현 및 Drag 전환은 PIE 수동 QA 필요

### Notion 요약 후보

- 인벤토리 아이템 Hover 시 이름·설명·무게를 표시하는 독립 Tooltip UserWidget 추가
- 중첩 아이템은 `개당 무게 × 수량 = 총 무게` 형식 제공
- Unreal 기본 Tooltip 배치로 화면 경계 보정 및 입력 비차단

## 인벤토리 아이템 우클릭 사용·장착

### 작업 목표

인벤토리의 소비 아이템은 우클릭으로 사용하고, 장비 아이템은 우클릭으로 즉시 장착하며 같은 부위의 기존 장비가 있으면 안전하게 교체한다.

### 주요 변경

- Item Data Asset에 소비 효과 설정값 `RestoreHealth`를 추가하고 스타터 포션 기본값을 25로 설정했다.
- 체력이 실제로 회복될 수 있을 때만 소비 아이템 수량을 1 감소시킨다.
- 최대 체력, 회복량 0, 잘못된 아이템 데이터에서는 소비하지 않는다.
- 장비 우클릭 시 Data Asset의 장착 부위에 즉시 장착한다.
- 기존 장비 교체 시 새 장비의 원래 Grid 위치를 먼저 검사하고, 맞지 않으면 모든 컨테이너에서 기존 장비의 MxN 크기에 맞는 빈 위치를 찾는다.
- 기존 장비를 돌려놓을 공간이 없으면 어떤 상태도 변경하지 않는 원자적 교체 규칙을 적용했다.
- 성공 시 인벤토리·장비 Delegate를 갱신하고 전투 로그에 회복량 또는 교체 아이템 이름을 표시한다.
- 우클릭 분기를 좌클릭 Drag 시작보다 먼저 처리해 Drag & Drop과 Hover 툴팁 경로를 유지했다.

### 검증

- `Rogue10mEditor Win64 Development` 빌드 성공
- 전체 메뉴 Widget Blueprint commandlet 컴파일 성공
- `ValidateMenuWidgetAssets.py` 0 errors / 0 warnings
- `CreateStarterItemAssets.py` Python 문법 검사 성공
- `git diff --check` 통과
- 실제 우클릭 입력과 체력·수량·교체 결과는 PIE 수동 QA 필요

### 확인할 점

1. 체력이 감소한 상태에서 포션 우클릭 시 회복 및 수량 감소 확인
2. 최대 체력에서 포션이 소비되지 않는지 확인
3. 빈 장비 슬롯 우클릭 장착 및 동일 부위 우클릭 교체 확인
4. 교체 장비가 새 장비의 원래 칸 또는 다른 유효한 MxN 빈 공간으로 이동하는지 확인
5. 빈 공간이 없으면 장착 상태와 인벤토리 상태가 그대로인지 확인
6. 좌클릭 Drag & Drop과 Hover 툴팁 회귀 여부 확인

## 장비 Drag Payload 좌측 상단 비행 수정

### 문제

장비창의 장착 아이템을 Drag하면 Payload가 최종적으로는 마우스를 따라오지만, Drag 시작 순간 화면 좌측 상단에서 커서까지 날아오는 현상이 남아 있었다.

### 원인 분석

- 장비창 전체 UserWidget이 Drag Source로 등록되어 있었다.
- 장비창 바깥 UserWidget은 Viewport 전체 크기이므로 Source Geometry의 절대 시작 좌표가 화면 좌측 상단이었다.
- UE 5.8의 UMG DragDropOp는 Drag 시작 후 0.15초 동안 Source Widget 좌표에서 Pivot 계산 좌표까지 기본 보간한다.
- `CenterCenter` Pivot은 최종 위치만 커서 중심으로 맞추므로 잘못된 Source 시작 좌표까지 해결하지는 못했다.

### 해결

- 장착 아이템이 있는 슬롯 Canvas 위에 `URogue10mEquipmentDragSourceWidget` 투명 프록시를 미리 배치했다.
- 프록시가 MouseDown Hit-Test 경로에 포함되므로 Slate의 Drag 감지 경로 재구성 조건을 충족한다.
- MouseDown 시 같은 프록시를 Payload와 동일한 M×N 크기로 커서 중심에 이동했다.
- 화면 좌표를 부모 Canvas 로컬 좌표로 변환해 해상도와 UI Scale이 달라도 시작 위치가 맞도록 했다.
- Tooltip과 우클릭 장착 해제 메뉴 입력을 프록시에서 기존 장비창 로직으로 위임했다.
- Drop, Drag Cancel, 클릭 종료, 장비창 닫기에서 홈 Layout을 복원하고 장비 갱신·Destruct에서 프록시를 제거한다.

### 검증

- UE 5.8 엔진의 `SObjectWidget::OnDragDetected`, `FUMGDragDropOp::New`, `FUMGDragDropOp::OnDragged` 경로 대조 완료
- Rogue10mEditor Win64 Development UHT/C++ 빌드 성공
- 새 UnrealEditor-Cmd 프로세스의 `ValidateMenuWidgetAssets.py` 전체 메뉴 검증 통과
- `git diff --check` 통과
- `CheckGeneratedChanges.ps1` 통과, 기존 Unreal Binary Asset 변경 경고만 확인
- 최신 모듈을 로드한 PIE에서 장비 1×1 및 M×N Payload 첫 프레임 위치 수동 확인 필요

### Notion 요약 후보

장비 Drag Payload가 화면 좌측 상단에서 날아오던 원인을 UE 5.8 UMG의 0.15초 Drag Decorator 보간과 전체 화면 Drag Source Geometry로 특정했다. Payload와 같은 크기의 투명 Source 프록시를 커서 중심에 DPI 보정 배치해 첫 프레임부터 올바른 위치에서 Drag가 시작되도록 수정했으며, Drop·취소·창 종료 시 프록시 정리 수명주기도 추가했다. Editor UHT/C++ 빌드 검증을 완료했다.

## 인벤토리 이동 시 메뉴 위젯 중복 등록 경고 수정

### 증상

인벤토리 아이템을 이동할 때 `WBP_InventoryWindow`, `WBP_EquipmentWindow`, `WBP_SkillTreeWindow`가 이미 화면에 추가됐다는 Script Warning이 반복됐다.

### 원인

- 아이템의 Mouse Down 입력이 공통 메뉴 창 승격 경로를 호출했다.
- `BringMenuWindowToFront()`가 ZOrder를 바꾸기 위해 스택의 모든 메뉴 창에 `AddToPlayerScreen()`을 반복 호출했다.
- 이미 Viewport에 등록된 UserWidget을 다시 추가하면서 경고가 발생했다.

### 수정

- 초기 등록과 창 승격 진입점을 `BringMenuWindowToFront()`로 통합했다.
- Viewport에 없는 창만 `AddToPlayerScreen()`으로 최초 추가한다.
- 기존 창은 `UGameViewportSubsystem`의 Widget Slot을 조회해 `FGameViewportWidgetSlot::ZOrder`만 갱신한다.

- Rogue10mEditor Win64 Development 빌드 성공
- `git diff --check` 통과
- 최신 DLL을 로드한 PIE에서 아이템 반복 이동 후 경고 미출력 수동 확인 필요

### Notion 요약 후보

인벤토리 아이템 이동 때 메뉴 위젯이 이미 화면에 추가됐다는 경고가 반복된 원인을 메뉴 최상단 승격 로직의 `AddToPlayerScreen()` 재호출로 특정했다. 메뉴 위젯은 최초 한 번만 화면에 등록하고, 이후에는 `UGameViewportSubsystem`의 기존 슬롯 ZOrder만 갱신하도록 변경해 중복 등록 경로를 제거했다. Editor C++ 빌드를 통과했으며 최신 모듈 PIE 로그 확인이 남아 있다.
