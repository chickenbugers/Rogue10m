## Sprint#3-2 - 몬스터 영역 스포너

### 작업 목표

레벨의 일정 Box 범위 안에서 지정한 몬스터를 최대 N마리까지 생성하고, 설정에 따라 처치된 몬스터를 일정 간격으로 보충하는 스포너 Actor를 제작했다.

### 주요 변경

- `ARogue10mMonsterSpawner` C++ Actor 추가
- `Spawn Area` Box 기반 임의 위치 선정
- 특정 `ARogue10mBasicMonster` 자식 Blueprint 클래스 지정
- 최대 생존 수와 시작 즉시 충원 옵션 추가
- 지속 보충과 일회성 생성을 선택하는 `Maintain Population` 옵션 추가
- Tick 대신 반복 타이머 사용
- WorldStatic 지면 라인 트레이스와 Spawn 충돌 처리 적용
- 약한 참조와 파괴 Delegate로 생성 몬스터 추적
- 사망했지만 파괴되지 않은 몬스터도 생존 수에서 제외
- 서버 Authority에서만 생성
- Blueprint 수동 생성·최대 충원·생존 수 조회 API 제공

### 검증

## Sprint#3-3 - 모험가 기본 직업과 좌클릭 주먹 공격

### 작업 목표

캐릭터 선택 화면에서 선택한 종족별 Pawn이 스폰된 뒤 기본 직업 `모험가`와 맨손 기본 공격을 부여받고, 좌클릭으로 Primary 주먹 공격을 실행할 수 있도록 구성했다.

### 원인과 설계

기존 좌클릭 입력 전달 자체는 정상적으로 구현되어 있었지만 CombatComponent의 로드아웃 적용이 `BeginPlay`에만 의존했다. 선택 CharacterClass로 만든 Pawn은 `BeginPlay` 이후 Controller가 Possess하고 PlayerState가 연결되므로, 스폰 시점에 기본 무기와 Ability 적용이 누락될 수 있었다.

기본 설정은 CharacterData가 소유하고, 실제 런타임 직업·무기 상태는 PlayerState가 소유하도록 경계를 정리했다. Character는 `PossessedBy`와 `OnRep_PlayerState`에서 CombatComponent의 단일 초기화 진입점을 호출한다.

### 구현 내용

- CharacterData에 `JobName`을 추가하고 기본값을 `모험가`로 지정
- PlayerState 기본 직업명을 `모험가`로 변경
- 종족명이 직업명을 덮어쓰는 프로필 적용 오류 수정
- CombatComponent에 `InitializeSpawnedLoadout()` 추가
- Possess 및 PlayerState 복제 완료 시 CharacterData·무기 Profile·GAS Ability 재적용
- `DA_Character_Default` 기본 무기를 `Unarmed`로 설정
- Unarmed Profile의 Primary 슬롯을 맨손 주먹 공격 Data Asset에 연결
- BP_FirstPersonCharacter의 CombatComponent 참조 저장
- UE Unity 빌드에서 발생한 Preview Actor 상수 재정의 오류 수정

### 검증 결과

- Unreal Engine 5.8 Rogue10mEditor Win64 Development 전체 빌드 성공
- 모험가/Unarmed/Primary 주먹 공격 Editor Python 검증 성공
- Human·Dwarf·Orc 남녀 6개 상속 Character 및 6개 Retarget AnimBP 검증 성공
- 좌클릭 Press/Release에서 Combat Primary 슬롯까지 코드 경로 확인
- Windows 샌드박스 ACL로 실제 마우스 자동화가 차단되어 에디터 재시작 후 수동 PIE 체감 확인은 남음

### 변경 파일 요약

- Character, CombatComponent, PlayerState, CharacterData: 스폰 후 로드아웃·직업 적용
- DA_Character_Default, BP_FirstPersonCharacter: 모험가·Unarmed 에셋 설정
- ConfigureAdventurerUnarmedSpawn.py: 설정과 회귀 검증 자동화
- CharacterDataOwnership 및 Feature 문서: 데이터 소유권과 실행 흐름 기록

## Notion 요약 후보

> 캐릭터 선택 후 Pawn이 스폰·Possess되는 시점에 기본 직업 `모험가`, 기본 무기 `Unarmed`, 좌클릭 Primary 주먹 공격을 재적용하도록 초기화 흐름을 개선했다. CharacterData가 기본 설정을 소유하고 PlayerState가 런타임 상태를 소유하며, PossessedBy/OnRep_PlayerState에서 CombatComponent가 로드아웃과 GAS Ability를 다시 구성한다. UE 5.8 전체 빌드와 Editor Python 에셋 검증, 6개 상속 캐릭터 검증을 통과했다.

## Sprint#3-5 - 몬스터 Behavior Tree 전투 AI

### 작업 목표

몬스터가 플레이어를 무조건 매 프레임 추적하지 않고, 홈 위치 주변에서 제한적으로 순찰하다가 거리 감지 또는 피격 조건으로만 전투를 시작하도록 UE 5.8 표준 AI 구조를 적용했다. 동시에 캐릭터 선택 로비의 불필요한 상태 텍스트, 프리뷰 방향, 배경 비율을 보완했다.

### 주요 구현

- `ARogue10mBasicMonster`의 Tick 기반 추적 제거
- `ARogue10mMonsterAIController`와 `UBTTask_Rogue10mMonsterDecision` 추가
- AI Perception Sight/Damage Sense로 거리 감지와 피격 어그로 처리
- 홈 위치, 순찰 반경, 추적 해제 거리, 기억 시간, 최대 추격 거리 적용
- NavMesh 기반 무작위 순찰, 목적지 도착 뒤 순찰 대기, 추적 해제 후 홈 복귀
- 공격 거리 안에서는 기존 몬스터 공격 로직을 재사용
- 몬스터 데이터 적용이 `OnPossess`보다 늦을 수 있는 UE 생명주기를 고려해 `BeginPlay` 후 AI 재초기화
- `/Game/AI/Monster/BB_Monster`, `/Game/AI/Monster/BT_Monster` 생성
- 25개 몬스터 데이터 에셋에 BT 연결 및 거리 관계 정규화
- 외부 BT/BB 누락 시 런타임 기본 트리로 복구
- `UI_StatusText` 제거, 프리뷰 정면 배치, 로비 배경 16:9 전체 채움

### 검증 결과

- Monster Behavior Tree AI Validator 통과: Blackboard 8키, Decision/Wait Task, 몬스터 데이터 25개

## Notion 요약 후보 - 몬스터 Behavior Tree 전투 AI

> 몬스터 AI를 Tick 기반 무조건 추적에서 UE 5.8의 AIController, AI Perception, Blackboard, Behavior Tree, NavigationSystem 구조로 교체했다. 몬스터는 홈 반경 안에서 순찰하고 시야 거리 또는 피격으로 플레이어를 인식하며, 공격 거리에서는 기존 공격을 실행한다. 대상이나 몬스터가 최대 추격 거리를 벗어나거나 기억 시간이 만료되면 타깃을 해제하고 홈으로 복귀한다. 25개 몬스터 데이터에 공통 BT를 연결했고 외부 에셋 누락 시 런타임 기본 트리로 복구한다. 로비에서는 UI_StatusText를 제거하고 3개 캐릭터 프리뷰를 정면으로 맞췄으며 배경을 16:9 전체 영역에 채웠다. UE 5.8 빌드와 에셋 Validator를 통과했으며 NavMesh 기반 PIE 체감 QA가 남아 있다.
