[개발 작업] Sprint#1-14 인벤토리 아이콘 런타임 표시 수정

- 증상: Item Data Asset과 UImage Brush에는 Texture가 연결되어 있었지만 PIE에서는 InventoryTint 배경만 보이고 실제 아이콘 픽셀이 표시되지 않았다.
- 진단: Unreal에서 다시 Export한 PNG의 RGB/Alpha 데이터와 런타임 Brush resource_object는 정상이었다.
- 원인: InitializeGridItem()이 위젯을 Canvas에 추가하기 전에 호출되며, UE5.8의 UImage::SetDesiredSizeOverride()는 내부 SImage가 생성된 뒤에만 값을 적용하므로 계산한 크기가 버려졌다. 원본 256~768px Brush가 44px 셀 영역에서 잘려 아이콘이 사실상 보이지 않았다.
- 수정: ScaleBox 의존성을 제거하고 Texture 크기, InventorySize, 44px CellSize, InventoryIconScale로 Fit 크기를 계산한 뒤 FSlateBrush::SetImageSize()와 UImage::SetBrush()로 생성 전에도 유지되는 크기를 저장했다.
- 추가: Tint Border 안에 UImage를 직접 배치하고, 아이콘이 있는 일반 상태의 Tint Alpha를 최대 0.18로 낮췄다. 스타터 Texture는 프로젝트에서 검증된 TC_DEFAULT + TEXTUREGROUP_UI + FROM_TEXTURE_GROUP 설정으로 통일했다.
- 검증: Rogue10mEditor Win64 Development 빌드 성공, 메뉴 Widget Blueprint 7종 컴파일/필수 위젯/클래스 참조 검증 성공.
- PIE 캡처 검증: 포션(수량 5), 장검, 투구, 갑옷, 부츠, 반지 아이콘이 각각 NxM 슬롯 내부에 원본 종횡비로 표시되는 것을 확인했다.

[Notion 정리 후보]
제목: UE5.8 UImage 생성 전 DesiredSizeOverride 유실로 인한 인벤토리 아이콘 미표시 수정
요약: CreateWidget 직후 Canvas에 추가하기 전에 호출한 SetDesiredSizeOverride는 내부 SImage가 없어 적용되지 않았다. 계산된 Fit 크기를 FSlateBrush ImageSize에 저장하고 SetBrush로 반영해 NxM 인벤토리 아이콘을 정상 표시했다.
검증: Editor Target 빌드 성공, WBP 자동 검증 통과, PIE에서 스타터 아이콘 6종과 프로토타입 아이콘 표시 확인.
