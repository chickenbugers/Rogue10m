# 2026-07-25 개발 로그

## 장비창 Scene Capture 매 프레임 경고 수정

### 원인

장비창을 열 때 `SetPreviewActive(true)`가 실시간 프리뷰를 위해 `bCaptureEveryFrame`을 활성화한 뒤 같은 함수와 장비 변경 경로에서 수동 `CaptureScene()`도 호출했다. UE 5.8은 매 프레임 자동 캡처 상태에서 명시적 캡처가 요청되면 같은 프레임의 중복 렌더로 판단해 비효율 경고를 출력한다.

### 변경 사항

- 장비창이 열려 있을 때는 `bCaptureEveryFrame`을 유지해 캐릭터 포즈를 실시간 표시한다.
- `SetPreviewActive(true)`의 즉시 수동 `CaptureScene()` 호출을 제거했다.
- `CapturePreview()`는 `bCaptureEveryFrame=false`일 때만 명시적 캡처를 수행하도록 보호했다.
- 이동 기반 자동 캡처 `bCaptureOnMovement`는 비활성화해 별도 중복 경로를 만들지 않는다.
- 창 닫기 시 자동 캡처·조명·프리뷰 메시를 비활성화하는 기존 수명주기를 유지했다.

### 검증

- Rogue10mEditor Win64 Development 빌드 성공
- 프로젝트 소스에서 `bCaptureEveryFrame` 상태의 수동 `CaptureScene()` 호출이 보호되는 것을 확인
- `Scripts/CheckGeneratedChanges.ps1` 및 `git diff --check` 검사
- 실행 중이던 에디터에는 이전 프리뷰 인스턴스가 존재할 수 있으므로 에디터 재시작 후 PIE 로그 수동 확인 필요

## Notion 요약 후보

장비창 캐릭터 프리뷰가 매 프레임 자동 캡처 상태에서 수동 `CaptureScene()`까지 중복 호출하던 문제를 수정했다. 활성 장비창의 실시간 캐릭터 포즈는 유지하되 수동 캡처는 자동 캡처가 꺼진 초기화 시점에만 허용해 UE 5.8의 비효율 경고를 제거했다.

## 장비창 Preview Character 좌클릭 회전

### 작업 목표

장비창 캐릭터 프리뷰 영역에서 좌클릭 드래그로 캐릭터를 좌우 회전할 수 있도록 구현했다.

### 변경 사항

- Scene Root 아래에 프리뷰 메시 전용 `PreviewMeshRoot` Pivot을 추가했다.
- Scene Capture 카메라와 3점 조명은 고정하고 프리뷰 Skeletal Mesh만 Yaw 회전하도록 분리했다.
- `UI_CharacterPreviewImage` 내부에서 시작한 좌클릭만 회전 입력으로 처리한다.
- 마우스 캡처를 사용해 프리뷰 밖으로 드래그해도 입력을 유지한다.
- 화면 가로 이동 1픽셀당 기본 0.35도 회전하며 WBP 클래스 기본값에서 감도를 조절할 수 있다.
- 좌클릭 해제, 버튼 상태 손실, 마우스 캡처 손실, 창 닫기, Widget 파괴 시 회전 상태를 정리한다.
- 장비 변경으로 프리뷰 메시를 다시 생성해도 현재 Pivot 회전 각도는 유지한다.
- 타이틀 바 창 이동, 장비 슬롯 Drag & Drop, 우클릭 장착 해제 입력 경로는 유지했다.

### 검증

- UE 5.8 UHT 통과
- Rogue10mEditor Win64 Development 빌드 성공
- 프리뷰 메시 Pivot과 카메라·조명 Attach 계층 분리 확인
- 회전 시작·종료·마우스 캡처 손실 코드 경로 확인
- `Scripts/CheckGeneratedChanges.ps1` 및 `git diff --check` 검사
- 실행 중 에디터가 핫리로드 모듈을 사용하므로 재시작 후 PIE 수동 확인 필요

### 남은 수동 QA

- 좌우 드래그 방향과 기본 감도
- 프리뷰 밖 시작 및 프리뷰 밖 버튼 해제
- 창 이동과 장비 Drag & Drop 회귀
- 장비 교체 후 각도 유지 및 Scene Capture 경고 미발생

## Notion 요약 후보

장비창 캐릭터 프리뷰에 좌클릭 좌우 드래그 회전을 추가했다. 메시 전용 Pivot만 회전해 카메라와 조명 구도를 유지하며, 마우스 캡처 손실과 창 닫기까지 입력 상태를 안전하게 정리한다. 회전 감도는 기본 0.35°/px이며 Widget Blueprint 클래스 기본값에서 조절할 수 있다.

## 몬스터 처치 경험치 및 25종 Data Asset

### 작업 목표

몬스터 처치 보상을 실제 플레이어 경험치 성장 경로에 연결하고, 일반·중간 보스·최종 보스 등급별 몬스터 Data Asset 25종을 준비했다.

### 변경 사항

- 마지막으로 피해를 준 플레이어에게 몬스터 사망 시 경험치를 1회 지급한다.
- 경험치 변경은 서버 권한에서만 수행하고 기존 `bIsDead` 상태로 중복 지급을 차단한다.
- 처치 보상은 전투 로그와 `LogRogue10m`에 몬스터 이름 및 경험치 수치로 출력한다.
- Data Asset 미연결 기본 몬스터는 10 경험치를 지급하고, 연결된 몬스터는 `ExperienceReward` 값을 사용한다.
- Monster Data Asset에 일반·중간 보스·최종 보스를 구분하는 `MonsterRank`를 추가했다.
- 공격 스킬이 없는 몬스터의 기본 공격 범위·피해·간격도 Data Asset에서 조정할 수 있게 했다.
- 일반 20종, 중간 보스 4종, 최종 보스 1종을 `/Game/DataAsset/Monster` 아래 등급별 폴더에 생성했다.
- 25종 단일 원본 정의, 멱등 생성 스크립트, 전용 Validator를 추가했다.

### 로스터 밸런스 초안

- 일반: Lv.1~20, 경험치 18~140, HP 70~500
- 중간 보스: Lv.8/12/16/20, 경험치 300~900, HP 1,200~3,200
- 최종 보스: Lv.25, 경험치 3,000, HP 10,000

### 검증

- UE 5.8 UHT 및 Rogue10mEditor Win64 Development 빌드 성공
- Unreal Python Validator에서 정확히 25종 및 등급별 20/4/1 수량 통과
- MonsterId·경로 중복 없음, 경험치·HP·공격 수치 양수, Skeletal Mesh 참조 유효 확인
- `Scripts/CheckGeneratedChanges.ps1` 및 `git diff --check` 통과
- 실행 중 에디터가 핫리로드 모듈을 사용하므로 재시작 후 처치 경험치 수동 QA 필요

### 남은 수동 QA

- 일반·중간 보스·최종 보스 처치 시 HUD 경험치와 전투 로그 확인
- 동일 몬스터 중복 지급 방지 확인
- 환경 피해 및 플레이어 외 공격 처치의 보상 미지급 확인


## Notion 요약 후보

몬스터 처치 경험치를 서버 권한의 마지막 공격자 PlayerState에 1회 지급하도록 연결했다. Monster Data Asset은 일반·중간 보스·최종 보스 등급과 기본 공격 수치를 포함하도록 확장했으며, 일반 20종·중간 보스 4종·최종 보스 1종의 총 25개 에셋을 생성했다. 전용 Validator로 수량 20/4/1, 경험치와 전투 수치, 메시 참조 및 중복 여부를 검증했다.

# 캐릭터 커스터마이징·생성·접속 시스템

## 작업 목표

게임 시작 시 3개의 캐릭터 슬롯에서 캐릭터를 생성·선택하고, 선택한 캐릭터 외형으로 게임에 접속하는 흐름을 구현했다.

## 주요 변경

- 종족은 인간·드워프·오크, 성별은 남성·여성으로 구성했다.
- `/Game/StylizedCharacter/Meshes/Character`의 전신, 머리, 눈, 헤어, 수염·귀걸이·피어싱·엄니, 문신 에셋을 조사해 6개 아키타입 카탈로그로 구성했다.
- 이름과 외형을 저장하는 최대 3슬롯 `CharacterProfileSubsystem` 및 SaveGame을 추가했다.
- 빈 슬롯 생성, 캐릭터 선택, 두 번 확인 삭제, 접속, 랜덤 외형을 지원하는 캐릭터 로비를 제작했다.
- 프리뷰 캐릭터는 온디맨드 Scene Capture를 사용하고 좌클릭 가로 드래그 회전을 지원한다.
- 접속 시 선택 프로필을 플레이어 메시와 PlayerState 이름·종족 표시에 적용하고 기존 1인칭 팔과 전투 입력은 유지했다.
- 장비창 프리뷰가 숨겨진 Manny 대신 현재 표시 중인 커스텀 메시를 사용하도록 보완했다.

## 데이터 및 저장 범위

- `DA_CharacterCustomizationCatalog`: 인간·드워프·오크 남녀 6개 종족·성별 조합의 메시·머티리얼 정의
- `WBP_CharacterLobby`: 3슬롯 선택과 생성 UI
- 로컬 SaveGame: 캐릭터 ID, 이름, 종족, 성별, 외형 선택값, 현재 선택 슬롯
- 인벤토리·장비·경험치·스탯·월드 진행 저장은 후속 통합 캐릭터 저장 작업으로 분리

## 검증

- UE 5.8 UHT 및 Rogue10mEditor Win64 Development 빌드 성공
- Unreal Python Validator에서 6개 아키타입, 필수 메시·선택 배열, 위젯 바인딩, 카탈로그 CDO 연결 통과
- `Scripts/CheckGeneratedChanges.ps1` 및 `git diff --check` 통과
- 실행 중 에디터는 핫리로드 모듈을 사용하므로 재시작 후 생성·저장·접속 및 애니메이션 수동 QA 필요

## 후속 확인

- StylizedCharacter 전신 메시의 서로 다른 Skeleton에 대한 전용 IK Retargeter와 AnimBP 제작
- 캐릭터 프로필 ID를 인벤토리·진행도 저장 데이터와 연결

## Notion 요약 후보

게임 시작 시 3슬롯 캐릭터 로비에서 인간·드워프·오크 남녀 캐릭터를 생성하고 선택한 캐릭터로 접속하는 시스템을 구현했다. StylizedCharacter 에셋을 기반으로 6개 아키타입 Data Asset과 외형 프리뷰 UI를 구성했으며, 이름과 외형은 로컬 SaveGame에 저장한다. UE 5.8 빌드와 Unreal Python Validator를 통과했고, 전용 Skeleton 리타기팅은 애니메이션 품질 개선 후속 작업으로 분리했다.
