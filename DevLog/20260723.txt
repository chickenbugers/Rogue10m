## HUD Quick Slot USTRUCT 초기화 오류 수정

### 원인

`FRogue10mHudQuickSlotView::InputSlot`만 기본 멤버 초기값이 없어 UE 5.8의 `AttemptToFindUninitializedScriptStructMembers` Smoke 테스트에서 `LogClass Error`가 발생했다. 이후 Automation 로그에 동일 오류가 수집되며 테스트 실패처럼 반복 표시됐다.

### 변경 사항

- `InputSlot` 기본값을 `ERogue10mAttackInputSlot::Primary`로 지정했다.
- Dodge와 아이템 Quick Slot은 별도 상태 필드로 구분되므로 기존 런타임 동작은 변경하지 않았다.
- `r.MotionVectorSimulation` 경고는 프로젝트 CVar가 아니라 UE 5.8 엔진의 등록 플래그와 TSR Render Thread 조회 불일치이므로 프로젝트 설정과 설치 엔진은 변경하지 않았다.
- 단독 `Condition failed` 15건은 UE 5.8의 엔진 테스트 코드에서 발생하는 로그이며 프로젝트 USTRUCT 오류와 분리했다.

### 검증

- Rogue10mEditor Win64 Development 빌드 성공
- `UObject.Class AttemptToFindUninitializedScriptStructMembers` Automation 테스트 성공
- 새 Automation 로그에서 `FRogue10mHudQuickSlotView::InputSlot` 및 `Uninitialized script struct members` 오류 0건 확인

## 시작 인벤토리 추가 갑옷

### 작업 목표

시작 장비 자동 장착은 유지하면서 플레이어 인벤토리에 가죽 갑옷 한 개를 추가로 제공했다.

### 변경 사항

- 기존 `DA_Item_LeatherArmor`를 시작 아이템 목록에 한 번 더 등록했다.
- 같은 부위에 시작 장비가 이미 장착된 경우 후속 장비의 자동 장착을 건너뛰도록 보완했다.
- 첫 번째 갑옷은 Armor 슬롯에 장착되고 추가 갑옷 한 개는 인벤토리 그리드에 남는다.

### 검증

- Rogue10mEditor Win64 Development 빌드 성공
- `Scripts/CheckGeneratedChanges.ps1` 통과
- `git diff --check` 통과

## Notion 요약 후보

기존 가죽 갑옷 Data Asset을 재사용해 시작 인벤토리에 갑옷 한 개를 추가했다. 자동 장착은 장비 부위당 첫 아이템만 처리하도록 변경해, 기존 가죽 갑옷은 장착 상태를 유지하고 추가 갑옷은 인벤토리에 남도록 했다.

## 캐릭터 기본 스탯 설계 및 장비창 표시

### 작업 목표

캐릭터의 기본값, 장비 증가량, 최종 런타임 값의 소유 관계를 정리하고 장비 변경 결과를 전투·생존·이동과 장비창에 동시에 반영했다.

### 기본값

- 최대 체력·스테미나·마나: 각 100
- 공격력: 10
- 방어력: 0
- 치명타 확률: 5%
- 치명타 피해: 150%
- 공격 속도: 100%
- 이동 속도: 600 cm/s
- 질주 속도: 900 cm/s

### 변경 사항

- Character Data Asset이 장비 적용 전 기본 스탯을 소유하도록 확장했다.
- InventoryComponent가 현재 장착 장비의 공격력·방어력·최대 체력·치명타 확률·공격 속도·이동 속도 보너스를 합산한다.
- Character가 기본·장비·최종값 스냅샷을 계산하고 AttributeSet과 CharacterMovement에 적용한다.
- 장착·교체·해제 성공 경로를 공통 스탯 갱신 함수로 통합했다.
- 스킬 피해에 최종 공격력을 더하고 피격 피해에서 최종 방어력을 차감한다.
- 방어 감소 후에도 양수 입력 피해는 최소 1이 적용된다.
- 장비로 최대 체력이 바뀔 때 현재 체력 비율을 유지한다.
- 장비창에 공격력, 방어력, 최대 체력, 치명타 확률, 공격 속도, 이동 속도를 `최종 (기본 + 장비)` 형식으로 표시한다.
- Character Data 기본값만 갱신하는 전용 Editor Python 모드와 회귀 Validator를 추가했다.

## Notion 요약 후보

캐릭터 기본 스탯의 기준값을 Character Data Asset에 정의하고, 현재 장착 장비 보너스를 InventoryComponent에서 합산해 AttributeSet과 CharacterMovement에 반영하는 흐름을 구축했다. 공격력은 스킬 피해에, 방어력은 정액 피해 감소에 적용되며 최대 체력 변경 시 현재 체력 비율을 보존한다. 장비창에는 공격력·방어력·최대 체력·치명타 확률·공격 속도·이동 속도를 최종값과 기본·장비 내역으로 표시한다.
