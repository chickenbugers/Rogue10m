# 2026-07-06 개발 로그

## 작업: 프로파일링 기록 구조 추가

### 작업 배경

- Rogue10m 개발 과정에서 UI, 전투, 몬스터, 맵 이동 기능이 늘어나고 있어 성능 측정 결과를 날짜별로 추적할 필요가 생겼다.
- DevLog는 개발 흐름 기록용으로 유지하고, 실제 성능 수치는 별도의 프로파일링 기록으로 분리하는 방향이 적합하다.

### 작업 내용

- `Profiling/README.md`를 추가해 프로파일링 기록 원칙, 권장 파일명, Unreal 측정 명령, 측정 우선순위를 정리했다.
- `Profiling/20260706_profiling.md`를 추가해 오늘 기준 프로파일링 기록 템플릿을 만들었다.
- 기록 항목은 FPS, Frame Time, Game Thread, Draw Thread, GPU, Slate/UI, Memory를 기본 기준으로 구성했다.

### 확인 필요

- 에디터 또는 패키징 빌드에서 `stat fps`, `stat unit`, `stat slate`, `stat gpu`, `stat memory` 측정값을 실제로 입력해야 한다.
- Unreal Insights Trace를 사용할 경우 `.utrace` 파일은 용량이 커질 수 있으므로 Git에 포함할지 별도 판단이 필요하다.

### Notion 정리 후보

- Rogue10m의 성능 기록은 `Profiling/YYYYMMDD_profiling.md` 형식으로 관리한다.
- UI가 Widget Blueprint 중심으로 전환되고 있으므로 HUD, 인벤토리, 장비창, 스킬트리, 설정창 표시 상태의 Slate 비용을 별도로 추적한다.
- Windows와 Android 모드를 분리해서 측정하고, 목표 FPS는 우선 60fps 기준으로 관리한다.
